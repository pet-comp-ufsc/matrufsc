# Guia de Contribuição

Para garantir que o desenvolvimento flua de forma organizada, produtiva e transparente para todos os colaboradores, estabelecemos algumas diretrizes essenciais que devem ser seguidas.

---

## Organização do Projeto

A gestão, planejamento e acompanhamento de todas as tarefas, melhorias e correções de bugs deste repositório são centralizados através de um **GitHub Project** associado ao repositório.

### Como trabalhamos:

1. **Quadro de Tarefas (Kanban):** Nosso fluxo de trabalho baseia-se em colunas clássicas (ex: _Backlog_, _A Fazer_, _Em Andamento_, _Em Revisão_ e _Concluído_).
2. **Issues:** Toda e qualquer modificação no código deve estar atrelada a uma _Issue_ ativa.
3. **Pegando uma Tarefa:**
   - Navegue pelo painel do projeto.
   - Escolha uma tarefa na coluna **A Fazer** (ou com a etiqueta `good first issue` se estiver começando).
   - Atribua a _Issue_ a si mesmo (`Assignee`) e mova-a para a coluna **Em Andamento** antes de iniciar o desenvolvimento. Isso evita duplicidade de esforço.

---

## Padrão de Commits (Conventional Commits)

Para mantermos o histórico do Git limpo, legível e propício para automações (como a geração automática de _changelogs_ e controle de versão semântica), adotamos estritamente a especificação dos **[Conventional Commits](https://www.conventionalcommits.org/)**.
